## CA-08 — Width / height meaning (all gate types)

### Verbatim (Italian)

```txt
la misure in latezza e larhezza riguardano strettamtne il cancello e non anche i pali
quelli non devono essere calcolati sono li solamete per bellezza quindi e la dimensione
comprensa fra i due pali in parole pover ogni pannello giustamtne dovra essere 1500
… resetera cosi per tutti i tipi di cancelli mentre per l'altezza si
“1000 = da terra al top rail; i railheads sono sopra e non contano nei 1000.”
```

### Reading

Width/height measure **only the gate leaf assembly in the clear opening between posts**. Posts are display/context, not part of the typed millimetres. Example: 3000 mm double swing → each leaf ≈ 1500 mm. Same rule for **all** gate types (extends CA-05 cantilever clear-opening rule). Height 1000 = ground to **top rail**; railheads sit above and are excluded from the typed height.

### Normalized rule — `CONFIRMED`

| Field | Meaning |
|---|---|
| `widthMm` | Clear opening between post **inner faces** (luce). Posts not included. |
| `heightMm` | Ground (or threshold datum) to **top rail**. Railheads / finials above do **not** count. |
| Applies to | All 8 `GateType` values. Cantilever tail remains **extra** on top of `widthMm` (CA-05). |

### Downstream impact

| Target | Change |
|---|---|
| `packages/gate-engine/src/rules/dimensions.ts` | Export confirmed meaning helpers + notes |
| `DimensionMeaningNote` | Confirmed copy for all types (cantilever keeps tail addendum) |
| CAD / marketing | Stop saying “provisional” for width/height datum |

## CA-09 — Bifold double: 2 panels per leaf, 50/50

### Verbatim

```txt
Sempre 2 pannelli per anta, 50/50
```

### Normalized rule — `CONFIRMED`

- `panels_per_leaf = 2` always for `bifolding_double_swing` and `single_bifolding`
- Equal split ratio `0.5`
- Double bifold → 4 folding panels total; single → 2

## CA-10 — Single bifold collection side

### Verbatim

```txt
Sempre sul lato cerniera; il cliente sceglie sinistra/destra in fase di preventivo
```

### Normalized rule — `CONFIRMED`

- Folded stack always collects on the **primary hinge side**
- Handing (hinge left vs right) is chosen **at quote / survey**, not invented as a fixed workshop default in the public UI
- Preview may show hinge-left as a schematic default and must label that handing is confirmed at quote

## CA-12 — Radius definition

### Verbatim

```txt
A e C puo essere sia curovo che dirtta la cima la il persocoso sara sempe curvo
```

### Reading

Travel path is **always curved**. Top profile may be **straight or curved** (A and C in the follow-up options — never straight-path-only).

### Normalized rule — `CONFIRMED`

| Aspect | Rule |
|---|---|
| Travel / track path | Always **curved** |
| Top profile | **Optional**: straight **or** curved (map curved top to `arched_top` / style choice) |
| Not a product | Straight-sliding leaf with only a decorative curved top and a straight track |
